# Contract/design scope

Own the API contract, migration examples and small compile-only feasibility examples.
Do not implement the full writer/reader redesign or change production temporal parsers.

The baseline already includes the writer improvements from #23-#27, binary membership
and the investigation benchmarks. Experimental patches are under benchmarks/experiments.

Resolve required inputs per scope, optional components, emission ordering, scratch-span
lifetimes, writer parent/child ownership, group count policy, duplicate/presence behavior,
projection lifetime and repeated getters. Reuse FixView concepts where feasible.

Make a recommendation with explicit tradeoffs. If a higher consumer TFM is necessary,
demonstrate the requirement rather than assuming an API break authorizes a TFM increase.
Label proposed behavior separately from current behavior in documentation.
